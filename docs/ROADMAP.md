# NOVA 技术路线图

路线图由真实自用场景驱动。日期是方向，不是承诺；每个阶段进入下一阶段前都必须满足退出标准。

## 阶段 0：可运行协议原型（已完成）

目标：用当前电脑证明一条多节点、可签名转账、可持久化的链能够端到端运行。

交付：

- 零第三方依赖的 Node.js 22 实现。
- 固定验证者、轮值提议者、2-of-3 提交签名。
- 原生 NOVA 余额、手续费销毁、账户 nonce。
- 本机 HTTP 节点网络、交易传播、区块同步。
- CLI、自动演示、协议测试和三节点集成测试。

退出证据：`npm.cmd test` 和 `npm.cmd run demo` 均成功。

## 阶段 1：确定真实用途与稳定协议

目标：让 NOVA 不只是“有一条链”，而是解决所有者的第一个真实问题。

计划：

- 根据 `docs/PRODUCT.md` 的五个问题确定第一个业务状态模块。
- 写出 v1 交易和查询协议规范，并增加版本兼容性测试。
- 增加结构化事件、交易回执、区块/交易查询和基础浏览界面。（文件 record 结构化事件、回执、查询和浏览器已完成；更多业务事件待真实需求确认）
- 增加加密 keystore、备份和恢复演练。（账户与验证者 keystore、链备份、状态重建、mempool/投票锁断电清理、后台 writer 优雅排空、换机恢复和三节点重启演练已完成；密钥轮换待完成）
- 为节点故障、重复交易、网络延迟和恶意输入增加故障测试。（节点掉线、磁盘落后、错误配置、重复交易、错峰启动、投票响应丢失、两个冲突锁收敛和基础恶意输入已覆盖；全验证者冲突锁、随机网络分区与模糊测试待完成）

退出标准：真实业务流程连续使用一周；链重启、备份恢复和节点追赶均有自动验证。v0.18 已完成不可补录的每日 readiness 采集、哈希链 journal、七日判定、同命令自动备份、链头推进竞态重试、首次使用感知的只读 preflight、单命令遮罩密码启动，以及 K&M 与 NOVA Explorer 的本地端口隔离；当前仍缺所有者实际连续七天使用所产生的证据，不能用自动测试替代。

## 阶段 2：分布式私人网络

目标：把验证节点放到至少三套独立运行环境，让单机故障不会停止整条链。

计划：

- 选择部署环境和私网方案，加入 TLS 与节点身份认证。（Ed25519 写请求认证、challenge 签名状态、多设备拓扑、独立密码和单节点 bundle 已完成；真实私网部署与 TLS 尚未完成）
- 将 JSON 存储迁移到支持原子提交、快照和校验的数据库。
- 增加指标、健康检查、日志聚合、告警和磁盘容量策略。
- 设计验证者增加、移除、密钥轮换和紧急停链流程。
- 根据威胁模型决定继续强化当前实现，或迁移到 CometBFT/Cosmos SDK 等成熟共识栈。（peer-first 投票与常见持久锁恢复已加固 crash-fault 活性；完整多轮 view-change 与 Byzantine 安全仍需成熟共识）

退出标准：关停任意一个节点后网络仍可用；从空数据恢复节点可以验证并追上链头；运维手册经过实际演练。当前已在同一测试主机的隔离目录中验证 bundle 网络、签名远程诊断、单节点掉线后的 quorum 备份、伪造状态与残缺链拒绝，以及用初始 bundle 和远程备份在全新目录重建替换节点；这些仍不能替代三台真实设备证据。

## 阶段 3：生产安全与可扩展能力

只有在 NOVA 要承载真实价值、第三方用户或公网节点时进入。

候选工作：成熟 BFT 共识迁移、安全审计、硬件密钥、治理、隐私、智能合约/EVM、跨链、轻客户端和公开浏览器。具体范围必须来自已验证的需求，不能为“功能齐全”而堆叠。

## CTO 当前建议

当前最大的不确定性不是 TPS、共识算法或编程语言，而是“这条链每天具体替你做什么”。在该答案明确前，不建议投入公网上线、发币经济模型、交易所、跨链或通用智能合约。这些都会扩大攻击面，却不会自动创造自用价值。
