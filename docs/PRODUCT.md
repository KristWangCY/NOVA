# NOVA 产品简报

更新日期：2026-08-11

## 产品愿景

打造一条由项目所有者独立掌控、可以长期自用的去中心化链。Codex 承担 AI CTO 的角色：负责技术拆解、实现、验证、风险提示和持续优化，并让没有区块链背景的所有者始终能理解和操作系统。

## 已确认需求

- NOVA 必须是一条独立运行的链，而不是仅部署在其他公链上的一个代币合约。
- 最终系统要能由所有者自用和控制。
- 研发过程允许持续加入新需求，架构需要支持渐进演化。
- Codex 应主动提出优化点和风险，不只被动完成编码指令。
- 操作和文档需要照顾区块链新手。

## 当前工作假设

这些是为了推进首版而采用的可撤销假设，不代表产品所有者已经最终确认：

- 首阶段是许可型网络，验证节点由所有者指定。
- 首阶段运行在同一台 Windows 电脑，随后再分布到不同设备或云主机。
- 首批业务能力是原生 NOVA 资产转账，以及不上传原文的个人文件哈希存证。
- 首阶段不提供 EVM 或通用智能合约；业务逻辑以原生状态转换逐步加入。
- 原生资产精度为 6 位，最小单位是 `unova`。

## 下一轮最有价值的产品输入

以下答案会决定下一个真实业务模块；文件存证只是可撤销的默认起点：

1. 这条链最先替你记录或完成什么？例如个人账本、积分、数字资产、设备事件、文件存证或自动化协作。
2. 谁会使用它？只有你、你的设备、熟人小组，还是未来允许陌生人加入？
3. 哪些数据必须公开、只对成员可见或完全不上链？
4. 节点最终会放在哪里？一台机器、家中多台设备、云服务器，还是不同所有者的机器。
5. 是否必须兼容以太坊钱包和 Solidity，或连接其他链？

## v0.12 优雅停机与 writer 生命周期

- [x] transaction gossip、定时同步、出块和持久化锁恢复统一登记为可排空后台任务。
- [x] stop 先拒绝新后台任务并关闭 HTTP，再等待在途请求和全部后台任务 settle，最后释放 `NodeHomeLock`。
- [x] 重复 stop 复用同一清理过程，不会提前释放或重复删除锁。
- [x] 锁释放后旧 Node 实例永久停止，不能重新启动后台任务、监听或调用节点 mutation 方法写 home。
- [x] 故障测试人为悬停在途 writer，确认排空期间第二实例仍被锁拒绝，writer 完成后新实例才能取得 home。
- [x] 明确强制进程终止无法优雅排空，仍依赖原子文件、签名链重放和 v0.10 崩溃恢复。
