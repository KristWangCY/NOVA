# ADR 0009：challenge 签名状态与 quorum 远程备份

- 状态：已接受
- 日期：2026-08-10

## 背景

v0.8 能把三个加密验证者身份安全拆分到不同设备，但初始化电脑保存的 node home 只是高度 0 副本。节点开始独立运行后，读取该目录不能说明远端是否在线、是否处于同一链头，也不能生成实时链备份。

直接信任远端 `GET /status` 或任意一台节点的 `/blocks` 不足以支撑恢复：私网地址可能配错，旧响应可能被重放，单节点可能损坏、被替换或提供分叉历史。另一方面，要求每次备份先停止并登录全部设备会削弱个人网络的可操作性，也会让“一台设备故障时仍可恢复”无法成立。

## 决策

### 1. 状态响应使用新 challenge 和验证者签名

管理端为每个请求生成独立 UUID challenge。节点以 `nova-signed-status` 独立 domain 签署 version、challenge、时间戳和精确字段的完整状态。管理端只接受 deployment 指定 URL 上、由 genesis 中预期验证者公钥签署、challenge 相同且位于 30 秒窗口内的响应，并核对链参数、身份、加密密钥标记、quorum、peer 认证和链头格式。

服务端不保存 challenge：新鲜度由管理端生成的不可预测 challenge 与时间窗共同保证。这避免增加持久化重放状态，但调用方必须为每个节点和每次重试生成新 challenge。

### 2. 诊断将“可达”“已认证”和“可操作”分开

- 不可达节点不是身份攻击；三节点中仍有两个已认证时报告降级警告。
- HTTP 可达但签名、身份、challenge、时间或字段无效视为安全失败。
- 少于 `ceil(2N/3)` 个已认证验证者不可操作。
- 已认证节点在相同高度报告不同区块哈希视为冲突并不可操作。
- 不同高度先报告同步警告，备份阶段再用完整链前缀判定。

### 3. 备份必须取得 quorum 份经过完整验证的链

管理端先完成签名诊断，再从每个已认证节点分页下载到其签名高度的完整区块链。每份候选都作为 `nova-chain-backup` v1 验证：校验创世块、每个 committed block、quorum 投票、交易执行和最终状态根；下载结果还必须匹配该节点刚签署的高度与区块哈希。

至少 quorum 份候选链必须完整通过。所有较短候选必须是最高候选的严格前缀，之后才把最高链以原有 `nova-chain-backup` v1 格式原子写盘。一个节点不可达或一份链下载失败可由其余 quorum 覆盖；任何可达节点返回无效签名状态则直接拒绝。

### 4. 远程运维保持只读和私网限定

诊断与拉链不读取远端私钥、不提交交易、不写节点 home。HTTP 仍必须由受控私网、VPN 或未来的 mTLS 承载；Ed25519 签名提供身份与完整性，不提供内容保密、流量隐藏、限流或抗拒绝服务。

## 后果

优点：

- 管理端可以在不登录每台设备、不持有验证者密码的情况下可信比较链头。
- 三节点中一台故障时仍能用其余 2-of-3 生成经共同历史验证的恢复材料。
- 输出格式没有变化，既有校验、恢复和旧链兼容测试继续适用。
- 伪造/重放状态、签名链头与下载链不一致、残缺链和历史分叉都有明确拒绝点。

代价与限制：

- 当前每次备份下载并在内存验证完整链，链增长后必须迁移到数据库快照、分段校验和增量备份。
- challenge 端点尚无限流，不能放到公网。
- quorum 个被攻陷或串谋的验证者仍可共同签署恶意历史；这继承 ADR 0001 的原型共识边界，不是生产级 BFT 保证。
- 自动测试只在同一主机的独立节点和故障服务器中完成；真实三设备、私网、防火墙、时钟和恢复演练仍是上线门槛。

## 被否决的方案

- **信任一台节点的裸 `/status` 和 `/blocks`**：无法抵抗地址误配、节点替换、单点损坏或旧响应。
- **只比较三个状态中的高度与哈希**：状态签名不能证明下载到的每个历史区块和状态转换有效。
- **要求三台全部在线才备份**：安全但失去单节点故障容忍，与三验证者网络的运维目标冲突。
- **把初始化目录当作远端镜像**：节点分发后立即陈旧，会生成外表有效但缺少新历史的备份。
- **改变备份持久化格式**：当前需求不需要；复用 v1 可减少恢复协议面和兼容风险。
