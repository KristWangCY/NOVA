# ADR 0010：从签名链恢复非最终状态并对投票锁失败关闭

- 状态：已接受
- 日期：2026-08-10

## 背景

NOVA 把 `chain.json`、`state.json`、`mempool.json` 和 `votes.json` 分别原子写盘，但一次区块提交需要依次更新多个文件。`state.json` 已被视为可重建派生数据：重启总是从签名链完整重放。mempool 和投票锁此前直接从磁盘读取，留下两个断电窗口：

1. 区块已经写入签名链，但包含的交易仍残留在旧 mempool；重启后过期 nonce 可使后续候选执行反复失败。
2. 区块已经提交，但对应高度的投票锁尚未删除；或者未提交的下一高度投票锁发生局部损坏。

两类文件的安全含义不同。mempool 是可以重新提交的非最终工作，丢弃无效项只影响可用性；投票锁证明本验证者已经签过某个提议，静默丢弃可能使节点在同一高度再次投票并破坏共识安全。

## 决策

### 1. 签名链仍是唯一恢复权威

节点取得 `NodeHomeLock` 后，先验证并重放完整 `chain.json`，得到可信链头和状态。所有 mempool 与投票锁恢复判断都以该结果为输入，不信任旧 `state.json`。

### 2. mempool 按确定性执行结果清理

启动时按磁盘顺序在可信状态副本上执行每个候选交易。执行成功的项保留，并影响后续候选的 nonce 与余额判断；任何已提交、重复、签名错误、nonce 冲突、余额不足或格式无效的项丢弃。顶层不是数组或 JSON 语法损坏时重置为空；读取权限和其他 I/O 错误仍中止启动，避免把磁盘故障误当作空 mempool。

清理结果在节点开始监听前原子回写。mempool 不进入链备份，因此这不改变任何协议哈希、签名载荷或恢复格式。

### 3. 投票锁按安全边界分级处理

- 高度小于或等于已提交链头的锁已被最终链覆盖，属于提交后清理残留，可以删除。
- 只允许保留恰好 `tip.height + 1` 的锁。
- 保留锁必须具有精确顶层字段，proposal 必须扩展当前链头并通过确定性执行、提议者签名和状态根验证，vote 必须属于本节点并通过 Ed25519 验证，记录哈希必须等于 proposal 哈希。
- 格式损坏、签名无效或指向更远高度时节点拒绝启动。操作者必须隔离节点并从共同链备份恢复，不能手工删除锁后继续签名。

### 4. 自动恢复必须可观察

运行时记录 `malformedMempool`、`discardedMempoolEntries` 和 `discardedCommittedVoteLocks`，并在任一值非零时输出 `recovered volatile state` 启动日志。日志只包含计数，不包含交易正文、私钥或密码。

## 后果

优点：

- 区块与 mempool 分文件提交的崩溃窗口不再导致节点长期停止出块。
- 有效 pending 交易在正常重启后继续保留，而不是粗暴清空全部非最终工作。
- 已提交投票锁可以自动收敛，未提交锁仍保持防双签语义。
- 没有修改链、交易、状态根、备份或签名格式，旧高度 221 链保持兼容。

代价与限制：

- 损坏的未提交投票锁会阻止该验证者自动启动，需要人工安全恢复；这是有意的安全优先选择。
- 当前 JSON 多文件持久化仍不提供数据库事务，新增逻辑只是让已知断电顺序可恢复；长期仍应迁移到带校验和原子批次的存储。
- mempool 修复只保留本机已有的有效候选，不保证其他节点一定保存同一 pending 交易；最终权威仍是 committed chain。
- 单轮投票锁在复杂网络分区后的活性限制仍继承 ADR 0001，不能描述为成熟 BFT view-change。

## 被否决的方案

- **启动时无条件清空 mempool 与 votes**：简单但会丢失有效 pending 工作，并可能让验证者忘记未提交投票后双签。
- **完全信任两个文件**：无法恢复区块先落盘、清理后落盘的合法断电窗口。
- **任何损坏都自动删除**：适合缓存，不适合共识安全锁。
- **把 mempool 和 votes 加入链备份**：二者都不是最终共识历史，会扩大恢复格式并把设备局部状态误当成网络权威。
