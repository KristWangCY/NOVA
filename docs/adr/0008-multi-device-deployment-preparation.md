# ADR 0008：多设备部署准备

- 状态：已接受
- 日期：2026-08-08

## 背景

到 v0.7 为止，三个验证者虽是独立进程和独立数据目录，却由同一台电脑、同一个密码和回环地址承载。直接把监听地址改为 `0.0.0.0` 不会自动得到安全分布式网络：创世 URL 会不可路由、四把密钥仍共享一个秘密、复制整个网络目录会把所有验证者私钥带到每台设备，而且初始化机的旧目录可能被误当成远端实时备份。

## 决策

- 增加不含任何密码值的 version 1 拓扑文件，精确声明 chain ID、供应量、私网传输要求、验证者 URL、本机监听地址和密码环境变量名。
- 多设备模式至少需要三个验证者；水龙头与每个验证者的环境变量名和密码值都必须唯一。
- 新生成的节点配置使用 version 2，分离 `listenHost` 和 `advertisedUrl`；加载和诊断继续兼容历史 version 1。
- 目前节点只提供 HTTP，所以拓扑拒绝数字形式的公网 IP，并要求 `private-network-required`。这不会创建或验证 VPN；私有 DNS、路由和防火墙仍由操作者负责。
- 为每个验证者生成带 SHA-256 校验和的单文件 bundle。bundle 包含共同创世、一个节点配置和一把加密验证者密钥，不能包含水龙头或其他验证者私钥。
- bundle 只允许在高度 0、节点未运行时生成；安装原子完成且不覆盖非空目录。
- 多设备初始化根目录只是部署源，远端启动后会陈旧，因此禁止对它使用网络级备份。现阶段应在停止的单个验证者设备上创建链备份。

## 后果

NOVA 现在可以在不复制全部私钥的情况下把三个验证者身份分发到三台设备，并让每个设备只持有自己的运行密码。自动测试已经从三个独立 bundle 目录组成网络并证明最终性。

这仍不等于完成多主机上线。请求正文在 HTTP 中可见，私网声明不能替代实际 VPN、ACL 或 mTLS，初始化电脑仍应被视为敏感密钥生成环境。真实退出标准需要所有者提供三台设备或三套独立主机，在实际私网中完成节点掉线、时钟偏差、重启追赶和备份恢复演练。

## 被拒绝的方案

- 把完整 `.nova/distributed` 复制到每台设备：每台机器都会得到全部验证者和水龙头 keystore。
- 在拓扑 JSON 中填写密码：容易进入版本控制、日志和聊天记录。
- 允许同一个密码保护所有 bundle：单一秘密泄漏会同时暴露 quorum。
- 自动相信 `0.0.0.0` 或私有地址代表安全：监听范围和网络访问控制是两件事。
- 把初始化机的高度 0 目录用于运行后网络备份：会生成通过本地校验但遗漏真实历史的旧快照。
