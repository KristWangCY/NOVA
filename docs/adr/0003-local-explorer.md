# ADR 0003：浏览器保持本地连接，不发布未认证节点

- 状态：已接受
- 日期：2026-08-08

## 背景

命令行和原始 JSON 足以验证协议，却不适合没有区块链背景的所有者长期观察网络。浏览器需要跨端口读取 `127.0.0.1:4101` 节点，但当前 HTTP API 没有 TLS、认证、限流或公网威胁模型。

## 决定

- 在仓库 `explorer/` 中提供 NOVA 专用本地区块浏览器。
- 浏览器默认只接受 `localhost` 或 `127.0.0.1` 节点地址，并把选择保存在设备本地。
- 节点只为 loopback 网页 Origin 返回 CORS 授权；远程 Origin 不获授权。
- 增加 `/overview`、最近交易、账户过滤和单区块只读查询，但不在浏览器中暴露节点内部投票接口。
- 浏览器不部署到公共托管服务。公网发布必须等待节点具备 TLS、认证、只读网关和限流。
- `npm run nova` 同时启动开发网和本地浏览器，保持新手可操作性。

## 视觉与交互方向

界面强调当前链高度、最终性和实际数据来源，不使用价格走势、投机收益或通用“加密货币”视觉。搜索统一识别区块高度、区块/交易哈希和 NOVA 地址。页面明确标注测试网络和真实资产禁用边界。

## 依赖风险

浏览器生产依赖执行 `npm audit --omit=dev` 后为 0 个已知漏洞。完整开发依赖审计仍报告 `vinext` 间接使用的 `image-size@2.0.2` 两项高危拒绝服务通告；截至本次实现，npm 没有不降级 vinext 的修复版本。

当前浏览器不会把图片或本地验证文件交给该解析依赖：v0.6 文件验证只使用浏览器 Web Crypto 计算 SHA-256，随后查询哈希。开发服务器也只在本机使用，所以暂时接受并记录该工具链风险。禁止用 `npm audit fix --force` 自动降级构建框架；待上游修复后升级。部署到公网前必须重新执行完整审计并解决该项。

## 后果

所有者现在能直观看到链是否活着、交易是否最终确认以及节点状态。代价是浏览器目前只能与本机链配合；分布到多台机器时需要增加安全只读网关，而不能简单放宽 CORS 或监听 `0.0.0.0`。

浏览器长时间实跑还发现原始 1.5 秒空块策略会快速膨胀个人链数据，因此同时调整为“有交易按 slot 出块、空闲时 30 秒心跳块”。这保留了可观测的网络活性，同时显著降低备份和同步成本。
