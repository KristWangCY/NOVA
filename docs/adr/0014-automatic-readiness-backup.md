# ADR 0014：在每日 readiness 锁内自动创建匹配链头的备份

- 状态：已接受
- 日期：2026-08-11

## 背景

v0.13 要求操作者先执行 `backup create`，再把文件交给 `readiness check`。为避免旧备份被错误关联到后来出现的冲突分支，备份头必须与 doctor 观察到的健康头完全相等。这个规则安全但对新手不友好：两个命令之间恰好产生新区块时，操作者只能理解错误、重新创建备份并再次输入长命令。

七日试验的目标是验证真实个人流程，而不是考验所有者能否手工处理正常链头推进。自动化可以减少步骤，但不能自动制造业务交易、补录日期、跳过 doctor 或放宽 exact-head 条件。

## 决策

### 1. 省略 `--backup` 进入自动模式

`readiness check --network|--deployment ... --tx ...` 在取得 `${journal}.lock` 后调用现有的 local 或 remote 备份实现。输出仍是标准 `nova-chain-backup` v1，默认保存在 `.nova/readiness/backups/nova-YYYY-MM-DD.json`，不增加新的备份格式或第二套验证器。

自动备份完成后重新运行对应 doctor，再按 v0.13 合同验证 chain ID、最终交易、同一伦敦日、时间顺序和完全相同的高度与 block hash。全部成立后才原子追加 journal。

### 2. 只对健康链头推进做三次有界重试

如果备份已完整验证、doctor 也健康，但高度或 block hash 不相等，说明两次观察没有获得同一个精确链头。自动模式丢弃本轮证据判断并重新创建备份，最多三次。每次都执行完整备份验证和 doctor，成功结果返回实际 `backupAttempts`。

备份 I/O、格式、checksum、签名、链重放、chain ID、交易查找、doctor、认证 quorum、冲突头或 degraded network 的任何错误都立即失败，不触发重试。三次仍无法匹配时明确失败，不降级、不写 journal。

### 3. 显式备份继续保持严格只读

提供 `--backup FILE` 时只读取操作者指定文件，最多尝试一次，不覆盖、不移动、不自动替换。这样审计、故障复现和完全手工运维仍有确定入口。

## 后果

优点：

- 日常流程从“交易、备份、登记”减少为“交易、登记”，更适合没有链运维经验的所有者。
- 自动化复用成熟备份验证，不复制共识或链校验逻辑。
- 正常新区块竞态可以自愈，同时重试原因和次数对 CLI/JSON 可见。
- journal 锁覆盖自动备份和最终追加，同一本地 journal 不会由两个 readiness writer 并发操作。

代价与限制：

- 自动模式可能执行三次完整备份，分布式大链的网络与磁盘成本高于手工模式。
- journal 锁持有时间延长；其他 readiness writer 会明确失败，而普通独立备份命令仍可并行读取链。
- 自动备份目录属于本地私密运行数据，不应提交 Git，也不能替代私钥与密码备份。
- 有界重试只改善正常竞态，不掩盖持续出块过快、网络不稳、分叉或验证错误。

## 被否决的方案

- **自动发送 dummy 交易后登记**：会把测试流量伪装成真实个人使用。
- **备份低于 doctor 时也接受**：摘要无法证明较旧备份仍属于当前健康分支。
- **所有错误都自动重试**：会掩盖签名、磁盘、认证和链损坏等需要立即处理的问题。
- **无限重试直到成功**：会让命令挂起并把不稳定网络包装成可用。
- **覆盖显式 `--backup`**：破坏操作者对审计输入的控制并隐藏原始故障证据。
