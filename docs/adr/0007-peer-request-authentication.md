# ADR 0007：验证者请求认证

- 状态：已接受
- 日期：2026-08-08

## 背景

v0.6 的 proposal、committed block 和内部 transaction gossip 只依赖正文中的共识或交易签名，没有证明 HTTP 请求来自哪个验证节点。只绑定 `127.0.0.1` 限制了攻击面，但如果直接改成多主机监听，任何能访问端口的主机都能反复触发投票、提交和解析路径。CORS 只约束浏览器，不是节点认证。

## 决策

在保持创世和持久化链格式不变的前提下，增加版本化 `ed25519-v1` peer 请求认证：

- 沿用创世验证者 Ed25519 密钥，但用 `nova-peer-request` domain 与区块、投票和交易签名隔离。
- 签名提交链 ID、发送与接收验证者地址、HTTP 方法、包含查询字符串的请求目标、原始正文 SHA-256、毫秒时间戳和 UUID request ID。
- 接收端只接受创世验证者，允许正负 30 秒时钟偏差，并以“验证者 + request ID”拒绝窗口内重放。
- 先验证签名再写入最多 10,000 项的内存缓存，避免未认证流量直接消耗缓存。
- 强制保护 proposal、committed block 和 `gossip=0` 交易传播；保留账户签名交易入口和经过区块共识校验的只读同步。
- `/status` 报告 `peerAuthentication: ed25519-v1`，网络 doctor 将其作为在线一致性条件。

## 后果

内部写请求的来源、目标与正文完整性现在可验证，捕获的请求不能在有效时间窗内重复执行。三类操作仍保持幂等或重复安全，因此节点重启清空缓存不会破坏共识安全。

请求签名不提供保密性、流量分析防护、限流或抗拒绝服务能力，也不能证明网络端点本身没有被转发。不同设备还会引入时钟同步要求。NOVA 因此继续只监听本机；多主机部署必须另行加入私网覆盖或 mTLS、独立节点密码、密钥轮换和实际故障演练。

## 被拒绝的方案

- 仅依赖 IP allowlist：地址可变化、可被错误配置，也不能保护正文完整性。
- 把 CORS 当作认证：非浏览器客户端不受 CORS 限制。
- 只签 JSON 解析结果：不同字节表示可能得到相同对象，无法绑定实际传输正文。
- 现在直接公开 HTTPS：证书生命周期、部署环境和私网拓扑尚未确定，过早开放监听会扩大攻击面。
