# ADR 0004：加密私人网络与节点目录独占运行

- 状态：已接受
- 日期：2026-08-08

## 背景

v0.3 的一键开发网仍把验证者和水龙头私钥保存为明文，而且多个进程可以同时打开同一个节点目录。前者不适合长期自用，后者可能让两个进程基于不同内存状态交错覆盖 `chain.json`、mempool 和投票记录。异常关机后的派生状态恢复也需要可重复验证，而不能依赖人工编辑 JSON。

## 决定

- 保留明文 `.nova/devnet` 作为明确标注的测试网络，新增独立的 `.nova/private` 安全启动路径。
- 私人网络的三个验证者与水龙头都使用既有 scrypt + AES-256-GCM keystore；配置只保存密码环境变量名称，不保存密码。
- `npm run nova:secure` 首次原子创建网络并启动三个节点与本地浏览器；初始化失败不会留下半成品目标目录。
- 每个 `NovaNode` 在读取或写入节点数据前，以排他创建方式取得 `node.lock`。锁记录 PID、随机实例 ID 与启动时间。
- 活动 PID 持有的锁必须拒绝第二个节点或恢复进程；已死亡 PID 的有效锁可以自动回收；格式损坏的锁默认拒绝自动删除。
- 释放锁时必须再次核对实例 ID，避免旧进程删除后来者的锁。
- 备份恢复使用同一把目录锁。
- 节点启动不信任 `state.json`，而是从创世状态确定性重放全部已提交区块并重新持久化派生状态。

## 后果

个人所有者现在可以用一条命令运行私钥落盘加密的网络；重复启动、备份误操作和常见异常退出不再容易造成并发写盘。链日志完整时，派生状态损坏可自动修复。

密码仍存在启动进程环境中，同一台机器上拥有相同用户权限的恶意程序可能读取它。当前单机初始化还让四把私钥共用一个密码，这是易操作性与隔离性的阶段性权衡，不适用于多主机网络。

PID 锁是本地文件锁协议，不是内核持有的跨主机分布式锁。PID 复用与极端文件系统故障仍可能需要人工核查；遇到无效锁时系统选择停止而不是猜测性删除。

## 后续工作

- 每验证者独立密码、隐藏交互式解锁、操作系统密钥库或硬件密钥支持。
- 验证者密钥轮换和紧急替换流程。
- 数据库事务、快照、增量备份与正式恢复时间目标。
- 多设备部署前加入 TLS、节点双向认证、网络访问控制和成熟 BFT 共识评估。
