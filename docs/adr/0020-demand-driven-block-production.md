# ADR 0020：按需出块并保留历史空块兼容

- 状态：接受
- 日期：2026-08-12

## 背景

真实 Day 1 运行显示，v0.19 每 30 秒生成的心跳空块占绝大多数链历史。空块不承载转账或文件存证，却持续增加三个节点的磁盘、备份与同步成本。节点已有独立 HTTP health、签名 status、定时同步和交易 gossip；这些活性路径不依赖新区块推进。

优化不得改写所有者的私人链、readiness journal 或备份，也不得让旧区块失效。升级期间还可能同时存在会提出空块的旧节点和不主动提出空块的新节点。

## 决策

v0.20 的 `producerTick` 只在 mempool 非空时安排新区块提议。`produceForSlot` 仍先同步并恢复当前高度持久化投票锁，然后再次检查 mempool；同步已提交本地交易时直接返回，不创建替代空块。

新网络配置不再写入 `emptyBlockIntervalMs`。旧配置允许保留该字段，但运行时忽略它，升级不会修改现有节点 home。

本决策只改变“何时主动创建新 proposal”，不改变区块或共识有效性：

- 历史空块继续按 block version 1 验证、重放、同步和备份。
- 新节点继续验证并投票给旧节点提出的合法空块，因此混合版本不会仅因交易列表为空而分叉。
- 已持久化的下一高度空 proposal 锁继续优先恢复；升级不能静默丢弃已签 vote。
- 交易进入 mempool 后，既有轮值提议、peer-first quorum 和故障恢复路径保持不变。

Explorer 以成功轮询节点 API 证明当前连接活性。mempool 为空时明确显示“节点在线 · 正常空闲”，不再把很久以前的最新区块时间暗示为停机证据。严格网络健康仍由 doctor 或签名远程诊断判断。

该标签只描述所连接节点当下可达且本地 mempool 为空。滚动升级期间，旧节点仍可提出合法空块，所以全部验证者升级重启前仍可能偶尔看到空块。交易池不按手续费排序；入池交易已按当前状态与既有队列顺序验证，提议按 FIFO 取配置上限，余下交易留在下一块，未达 quorum 时在后续合格 slot 重试。全验证者冲突锁或 Byzantine 阻塞仍属于既有共识限制。

## 未选择的方案

- **继续 30 秒空块**：简单但长期积累无业务数据，且健康检查已有独立通道。
- **把空块判为无效**：会让历史链和混合版本节点分叉，属于不必要的协议破坏。
- **自动删除历史空块**：会改变高度、previous hash、提交签名和 readiness 备份，破坏不可变历史。
- **升级时重写所有配置**：没有必要，且增加误改私人网络文件的风险。

## 验证

三节点测试向新节点注入极短的旧 `emptyBlockIntervalMs`，跨越多个旧间隔后确认高度仍为零；交易到达后仍完成三节点最终确认，随后再次空闲时高度保持不变。故障测试构造并持久化合法空 proposal 锁，确认两节点恢复提交、第三节点同步历史空块且链头一致。现有完整链验证、备份、远程同步、优雅停机与 Explorer 构建继续作为回归门禁。

真实三节点网络在 Day 2 重启并登记交易后，三个 API 持续在线、mempool 均为空，连续 35 秒观察期间三节点高度一致且保持不变。该检查只读，不修改 `.nova`。

## 结果

完全升级并重启的私人网络只为真实交易增长历史。已有空块永久保留且继续可验证。正在运行的旧进程不会因磁盘源码变化自动切换；所有者下一次使用遮罩启动器优雅重启后才采用 v0.20 行为。
