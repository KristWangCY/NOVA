# ADR 0013：以可核验的七日证据决定个人自用 readiness

- 状态：已接受
- 日期：2026-08-11

## 背景

NOVA 已能在单机运行三验证者，也已具备签名远程诊断、可靠链备份、崩溃恢复和优雅停机。项目仍然缺少一个更基础的产品证据：所有者是否能连续一周用它完成有实际意义的个人流程。只记录“服务启动成功”会奖励空转；自动生成无意义交易会把测试活动误报为产品使用；手工表格又无法证明交易、诊断和备份属于同一条链。

v0.13 需要一个本地工具，把每天的真实最终交易、当前网络健康状态和覆盖该交易的已验证备份绑定为可重复核验的证据，同时明确它不是链上共识、可信时间戳或第三方审计系统。

## 决策

### 1. 每日成功必须同时满足三类证据

一天只在以下条件全部成立时写入：

1. 操作者明确提供一笔已最终提交的 transfer 或 record 交易 ID；工具不自动制造交易。
2. 单机网络 3/3 验证者在线且同意一个链头；分布式网络至少有经过 Ed25519 签名认证的 quorum 在线且链头无冲突。
3. 标准 `nova-chain-backup` v1 已完整验证，属于同一 chain ID，覆盖该交易，并且其高度与区块哈希完全等于随后 doctor 观察到的健康链头。

交易区块时间、备份创建时间、doctor 检查时间和最终采集时间必须落在同一个 `Europe/London` 日历日。日期来自运行时系统时钟，不提供命令行日期参数，也不提供补录功能。

### 2. journal 采用精确字段和线性哈希链

`nova-readiness-journal` version 1 使用精确字段集合。每个 `nova-readiness-day` 条目保存交易、doctor 与备份的最小可验证摘要、`previousEntryHash` 和 `entryHash`；顶层另保存 `journalHash`。所有哈希均为 canonical JSON 的 SHA-256。

写入前重新验证完整历史，拒绝未知版本或字段、非严格递增日期、重复日期、重复交易、断裂哈希和跨链证据。一个日期最多一个条目；七日结果按连续伦敦日计算，间断后当前 streak 重新开始，但历史最长 streak 仍保留。

NOVA 当前没有独立的交易 Merkle tree，因此不生成伪造的 Merkle inclusion proof。journal 保存交易所在区块及已验证备份链头的摘要，权威验证仍来自标准链备份的逐块签名和状态重放。要求备份头与 doctor 头完全相同，避免在只保存摘要的前提下把较旧备份误关联到后来出现的冲突分支；若两步之间恰好产生新块，安全代价是操作者需要重建备份再检查。

### 3. 单 writer、原子落盘和可自动判定退出码

默认路径为 `.nova/readiness/journal.json`。采集采用 `${journal}.lock` 排他创建，活动 PID 阻止第二个 writer，死亡 PID 可回收；只有全部输入通过验证后才原子替换 journal。`readiness report --require-ready` 在尚无任意连续七日区间时返回状态 2，便于个人计划或监控显式区分“命令正常但尚未就绪”。

### 4. 安全声明必须限制在本地产品证据

线性哈希链能检测意外编辑、部分写入和未同步修改，但不能阻止控制本机的所有者重写整份历史并重算哈希。系统时钟也不是可信时间源。readiness 结果不得描述为数字签名、第三方见证、不可伪造审计、生产 BFT 认证或公网/资金上线许可。

## 后果

优点：

- “连续使用一周”从口头状态变为可以由 CLI 一致计算的退出证据。
- 每一天都绑定真实最终交易、当时网络健康和可恢复备份，不把空心跳当成使用。
- 单机与未来三设备网络共享同一 journal 合同，同时保留不同可用性阈值。
- 失败先于写盘，重复运行、并发运行和被篡改历史不会静默产生第二套结果。

代价与限制：

- 操作者必须每天在伦敦日期切换前完成交易、备份和登记；跨午夜证据会被拒绝。
- 本地系统时钟、时区数据库和文件仍由所有者控制，无法提供独立时间证明。
- journal 只保存协议摘要，不解释交易为何有意义；个人用途说明需要另行记录。
- 七日通过不会消除三台真实设备、私网、TLS、成熟存储、密钥轮换和生产共识方面的剩余风险。

## 被否决的方案

- **启动服务即记一天**：只能证明进程存在，不能证明链完成了个人工作或可以恢复。
- **每天自动发送 dummy 交易**：把自动测试伪装成产品采用，也浪费链空间。
- **允许 `--date` 补录**：使连续七日目标失去约束，且更容易产生跨午夜不一致。
- **只保存 Markdown/CSV 清单**：缺少精确版本、机器校验、链身份绑定和并发写保护。
- **宣称 Merkle proof**：当前协议没有交易 Merkle tree；用普通 SHA-256 摘要冒充 inclusion proof 会误导安全边界。
- **把 journal 上传公共服务签名**：会引入新的隐私、可用性和信任依赖，超出当前个人自用阶段。
