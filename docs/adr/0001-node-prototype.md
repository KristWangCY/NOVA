# ADR 0001：用 Node.js 构建首个 quorum-PoA 原型

- 状态：已接受
- 日期：2026-08-08

## 背景

项目所有者希望拥有一条自用的独立链，但目前没有区块链搭建经验。仓库开始时为空，当前电脑已有 Node.js 22，没有 Go、Rust、Docker 或可用的 WSL Linux 发行版。

成熟的应用链框架能避免重复实现共识和网络，但会同时引入新的语言、工具链、代码生成、节点配置和运维模型。项目当前最需要验证的是实际用途、操作体验和最小协议边界。

## 决定

v0.1 使用 Node.js 内置 API实现一个无第三方运行时依赖的许可型链原型：

- 三个固定 Ed25519 验证者按时间 slot 轮流提议。
- 每个验证者先确定性执行交易并验证状态根，再为提议签名。
- 三验证者中至少两个有效签名构成提交证明。
- 验证者在同一高度锁定第一次签署的提议，避免正常运行时重复签名。
- 区块、状态、mempool 和投票分别持久化为 JSON；启动时从创世区块重放链并重建状态。
- 所有节点接口默认只绑定 `127.0.0.1`。

协议代码与网络/持久化代码分层，方便未来替换共识和存储而保留业务状态转换及测试向量。

## 理由

- 当前环境可直接运行，所有者可以立即观察每个组成部分。
- 代码规模足够小，便于学习、审计和快速修改首个业务模块。
- 多进程节点、签名、投票、状态根和同步能验证关键工程假设。
- 不把尚未确定的产品需求过早固化进大型框架。

## 明确不保证的性质

该协议不是 PBFT、HotStuff 或 CometBFT 的重新实现，也不声称具有同等安全性：

- 2-of-3 quorum 的两个冲突集合只保证有一个交集验证者；若该验证者作恶并重复签名，可能形成冲突提交。
- 高度锁定降低重复签名风险；v0.11 已能用发送者签名锁证明恢复常见的丢失响应和两个冲突锁，但没有完整多轮 view-change，所有验证者锁在不同提议时仍可能需要人工恢复。
- slot 调度依赖主机时钟，没有完整的多轮超时、锁定和 view-change 证明。
- 固定验证者集合没有链上变更协议。
- JSON 多文件写入不具备数据库级原子性；启动重放可以修复部分写入，但不是完整灾难恢复方案。
- HTTP 网络没有为不可信公网设计。

因此 v0.1 只能使用测试资产。

## 迁移触发条件

满足任一条件时，必须在继续扩展前评估迁移到成熟共识实现：

- 承载不可轻易重建的真实价值或法律/财务记录。
- 验证者由互不完全信任的不同主体运营。
- 节点需要暴露到互联网或允许公开加入。
- 需要动态验证者、治理、惩罚或跨链通信。
- 手工故障恢复不再可以接受。

当前优先候选是 Cosmos SDK + CometBFT，因为它原生面向应用专用链，将共识/网络与确定性状态机分离，并支持许可型网络。若未来必须使用 Solidity 和以太坊工具链，再独立评估 Cosmos EVM 或其他 EVM 应用链方案。Polkadot SDK 保留为需要 Wasm runtime、无分叉升级或共享安全模型时的候选。

## 后果

正面：能立即运行、无安装负担、协议透明、迭代速度快。

负面：当前共识和存储必须被视为可替换原型；若真实用例被验证，需要承担迁移或显著加固成本。这个成本是有意接受的，因为它发生在需求有证据之后。
