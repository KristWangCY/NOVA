# ADR 0002：加密账户 keystore 与无私钥链备份

- 状态：已接受
- 日期：2026-08-08

## 背景

v0.1 开发网把所有 Ed25519 key record 写成明文 JSON，这适合自动化测试，却不适合个人长期保存账户。与此同时，只有链目录而没有可验证备份格式，会让操作者难以区分链数据、节点身份和资产所有权。

## 决定

- 普通 `account create` 默认生成 `nova-keystore` v1，不再默认输出明文私钥。
- 密码至少 12 个字符，只从 `NOVA_KEY_PASSWORD` 或用户指定的环境变量读取；CLI 不提供 `--password` 参数。
- 使用 scrypt（N=32768、r=8、p=1、32 字节随机 salt）派生密钥，使用 AES-256-GCM 和 12 字节随机 IV 加密。
- 地址、公钥、标签和格式版本作为 GCM 认证附加数据，公开元数据被篡改时解密失败。
- 明确标注的开发网验证者和水龙头保留明文测试私钥；长期自用的私人网络必须使用 ADR 0004 定义的加密启动路径。
- 链备份只包含创世配置和完整已提交区块，不包含任何私钥、mempool 或投票锁。
- 恢复必须先完整验证备份，并要求目标节点创世配置一致、目标验证者密钥属于该验证者集合。

## 后果

普通账户文件泄露不再等同于立即泄露私钥，但安全性仍取决于密码强度和本机环境。环境变量能避免密码进入 shell 参数历史，但拥有同一用户进程权限的恶意程序仍可能读取它。

链备份可以在不同验证节点之间复用；节点私钥和账户 keystore 必须另行备份。只有链备份不能恢复资产控制权，只有私钥备份也不能恢复完整历史，两者需要独立管理。

备份校验和用于发现意外损坏，不是外部信任锚。独立验证备份只能证明它内部自洽；恢复到现有节点时与该节点的创世配置比对，才证明它属于目标网络。

## 后续工作

- 交互式隐藏密码输入和操作系统密钥库集成。
- 每验证者独立密码、操作系统密钥库、硬件密钥和在线密钥轮换。
- 分片或硬件备份策略、实际恢复演练和恢复时间指标。
- 大规模链数据的增量快照和数据库备份。
