# ADR 0006：以链外原文、链上哈希实现第一项文件存证能力

- 状态：已接受
- 日期：2026-08-08

## 背景

截至 v0.5，NOVA 已能稳定运行、诊断和恢复，但除资产转账外没有能每天使用的业务能力。在所有者尚未指定最终场景时，文件与个人记录存证是一项低资金风险、可立即验证链价值且不强迫引入通用智能合约的默认起点。

直接把文档、照片或笔记原文写入链会永久泄露内容、快速膨胀每个节点和备份，并让删除请求无法满足。只保存哈希则能证明日后提供的字节与当时记录一致，同时把原文留在所有者控制的存储中。

## 决定

- 新增 version 1 `record` 交易类型，不修改历史 `transfer` 的签名载荷。
- record 提交固定 `sha256` 算法、64 位小写内容哈希、字节数、标题、分类、公开备注、作者、正手续费和账户 nonce。
- 文件内容、文件名与本地路径永不进入交易、状态或节点 API。
- record 和 transfer 使用同一 nonce 空间；record 只扣正手续费并销毁，不转移资产。
- 不在确定性状态中复制 record 索引。签名区块是唯一权威记录，查询暂时扫描完整链。
- 每种交易严格校验字段集合，拒绝任何未被签名载荷提交的额外字段。
- CLI 使用流式 SHA-256，并在哈希期间检查文件大小与修改时间没有变化。
- Explorer 允许选择不超过 64 MiB 的本地文件，在浏览器中计算 SHA-256 后只向本机节点查询哈希；大文件转向 CLI。
- 使用提交区块时间作为共识确认时间，不接受用户自报的可信创建时间。

## 兼容性证据

创世状态仍只包含高度、余额、nonce、供应量和累计销毁手续费。record 历史保存在区块而不增加状态字段，因此旧创世块和 transfer 状态根不变。实现完成后，v0.6 节点成功验证并重放仓库现有三个节点高度 221 的完整旧链。

## 后果与安全边界

验证成功证明“当前文件精确字节的 SHA-256 与某个最终确认 record 相同”，并把签名账户与提交区块时间关联起来。它不证明文件陈述为真、不证明原创、不判断法律效力，也不能证明该账户在链外的真实身份。

标题、分类、备注、字节数、作者地址和裸 SHA-256 对所有链参与者永久公开。低熵或已知候选内容可能被离线猜测后比对哈希；敏感文件即使不上链，也不应在没有额外随机承诺方案时记录裸哈希。

链扫描查询成本随历史线性增加。浏览器文件验证为兼顾内存设定 64 MiB 上限；CLI 流式实现没有该浏览器上限，但仍受本机文件系统与 Node 安全整数限制。

## 后续工作

- 为 record 建立可从签名链重建的本地索引，而不改变共识状态根。
- 增加目录清单、批量 Merkle 存证、版本关系与追加式更正记录。
- 设计带随机盐或承诺方案的敏感内容存证，并明确盐的备份责任。
- 根据所有者真实使用反馈决定记录模板、标签、导出和自动化监视目录。
