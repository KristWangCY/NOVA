# ADR 0005：网络级诊断与一致链备份

- 状态：已接受
- 日期：2026-08-08

## 背景

v0.4 已能安全启动和恢复单个节点，但所有者仍需要逐个读取 `/status` 并自行比较高度、哈希和密钥状态。单节点备份命令还要求人工选择来源；如果选到落后、配置错误或历史异常的节点，虽然单份链可能验证成功，操作者仍无法确认它代表网络当前最完整的历史。

## 决定

- 增加 `nova doctor`，从网络根目录发现创世验证者及其节点目录。
- 离线检查验证根创世、节点创世、验证者身份、节点编号、监听 URL、peers、密钥存储形态和完整签名链。
- 所有有效节点链必须共享共同前缀。较短链可以被识别为同步落后并告警；共同高度哈希不同属于失败。
- 如果配置的密码环境变量存在，诊断必须实际解锁每个加密验证者 keystore；密码缺失只告警，错误密码失败。
- 在线检查交叉验证节点名称、chain ID、验证者地址、加密状态、验证者数量、quorum、高度和区块哈希。
- 零节点在线默认表示“网络停止但可离线检查”，使用 `--require-online` 时改为失败；部分节点在线始终视为降级失败。
- 增加 `backup create --network`。只有全部节点目录通过验证且链历史无分叉时，才从最高的已验证节点创建现有 v1 备份。

## 后果

所有者获得一个面向决策的结果，而不必理解或手工比较多份 JSON。备份源由可验证证据选择，落后节点不会降低备份高度，损坏或配置漂移也不会被静默忽略。

诊断是某个时刻的快照，不等于持续监控或生产安全证明。节点可能在检查结束后立即变化；不同高度也可能只是正常同步。完整签名链只能证明当前协议规则下自洽，不能弥补简化共识本身缺少正式 BFT 安全证明的问题。

离线检查在没有密码时只能验证加密 keystore 的公开外壳，不能证明密码正确或密文可解；因此结果必须保留明确警告。网络级备份仍是完整 JSON 链，尚未解决大链的增量快照和保留策略。

## 后续工作

- 周期健康监控、结构化日志、指标与告警。
- 网络分区、慢节点、磁盘耗尽和协议模糊测试。
- 数据库快照、增量备份、备份保留与异地恢复演练。
- 多主机环境的安全管理平面和只读诊断端点。
